> 更新于 2026-11-04。描述跨窗改造提交 `fc45f22` 及当前工作区的字幕重译修复；以代码为准。
> 设计、交接、计划、验证记录与实验笔记归档到本机 `.ignore/development-docs/`，不随仓库发布。

## 一句话

Windows 上把系统内录或麦克风的音频，实时转成中文双语字幕。识别和翻译都跑本机
`llama-server`，字幕由独立的置顶悬浮窗渲染，三者之间用 WebSocket 协议解耦。

## 现在能做什么

| 能力 | 状态 | 说明 |
|---|---|---|
| 系统内录 | 可用 | 默认跟随 Windows 默认输出设备，换耳机/切显示器自动重开流 |
| 麦克风 | 可用 | 同上，也可在托盘里把设备钉死 |
| 双路同时 | 可用 | 句子/音频状态按源隔离，共用会话、翻译历史与翻译队列（见局限） |

| 语音证据 | 可选观测 | 本地 Silero ONNX 旁路，默认关闭；不据此拦截字幕 |

## 架构

### 三个进程

```
simulcast.app                总管：托盘、单实例、子进程生命周期（无音频、无模型）
 ├─ simulcast.cli run       识别引擎：采集 → 断句 → ASR → 翻译 → 发字幕
 └─ simulcast.render.qt     字幕引擎：只连 websocket，渲染悬浮窗
```

- 总管用 **Job Object**（`KILL_ON_JOB_CLOSE`）绑住两个子进程，总管被强杀也不留孤儿。
- 子进程输出重定向到 `logs/pipeline.log`、`logs/render.log`，总管自己写 `logs/app.log`。
- 崩溃策略：连续启动失败 3 次停下并标红；连续跑满 20 s 后计数清零。

### 数据流

```
音频帧 → EnergyVad → Segmenter(重叠窗口) → 同源有序 ASR → 逻辑句子管理器
      → MT 队列（定稿优先）→ 流式译文 → Hub → websocket → 悬浮窗
```

### 协议 v1

`ws://127.0.0.1:8765`，每帧一个 UTF-8 JSON，**按 id upsert**，客户端无状态可重连。

- `caption`：`id / source / t0 / t1 / raw / translation / state / lang / asr_ms / mt_ms / seq / sid`
- `snapshot`：连上时补发最近 120 条，解决中途接入
- `session`：`running / stopped / error`
- `eval`：分段质量指标（只落 jsonl，不上屏幕）
- `utterance_boundary`：预算降级、对齐歧义、未确认结束或翻译失败的诊断
- `asr_repair`：歧义边界补解码的音频范围及原文
- `asr_observation`：可选语音证据及对应 ASR 文本；这些诊断不作为字幕渲染
- `control`：`target=render|pipeline`，由 Hub 广播并回调管道，例如 `render.style`、`capture.device`

## 关键实现决定

**窗口与逻辑句**：音频窗口最长约 10 s，硬切后保留 1.5 s 重叠。每个源的 ASR 顺序处理，
窗口 ID 与字幕逻辑 ID 分开。草稿内句稳定后可提交；`hard` 和 `hard_pause` 都保留最后候选句，
不再按旧 carry 的 8 词/200 字符限制提前提交。下一窗口沿用待完成句子的 ID，
在实际重叠附近按字符归一化对齐，兼容中日文和切点标点变化；真实重复不按全局包含关系删除。
EOF 恰好落在硬切处时不再解码只有旧重叠音频的窗口，直接结束上一句。

对齐歧义会保留未决文本并记录原因；仅在待完成句子有精确音频区间且缓存完整时限次补解码。
已提交内句后，没有词级时间戳就无法安全排除前文，因此可能跳过补解码并显式降级。
待完成预算为 30 s 或 1000 字符，音频缓存为 30 s；预算耗尽仍可能分句。
旧 `carry_*` 配置兼容读取但不再使用。停顿及 ASR 标点都是启发式线索，不保证语义句界正确。

**失败与结束**：final ASR 失败、空结果或被守门全拒绝时，保留已显示草稿并以
`asr_unconfirmed` 结束待完成状态，不升级为定稿/正式历史。正常结束等待 ASR 与活动翻译；
超时或直接停止记录未确认结束并取消任务。原文已确认而翻译失败/超时时保留原文定稿，
用 `translation_incomplete` 诊断标记；已有译文可能只是未完成版本。
译文关联生成它的原文，只有对应当前原文的译文才可保留；旧原文的译文在最终失败时清除，
渲染与导出回退显示已确认原文。

**ASR 守门**：解码结果先过 `asr/guard.py` 再进管道——末段周期性复读按周期切掉，4-gram 多样性
过低视为退化整段丢弃，语言与配置不符丢弃，字符/秒超阈值丢弃。ASR 端 `repeat_penalty=1.05`
是实测值（1.1 会在歌词段自造续写）。`asr.guard=false` 可整开关掉。

**语音证据旁路**：`asr.speech_evidence_mode="observe"` 时读取本地 Silero ONNX，
对每个 ASR 窗口独立重置状态，记录平均语音分数及覆盖率。模型分数不是文字正确率。
已有困难对白存在漏检，因此当前没有自动幻觉拦截策略。默认 `off`，正常运行无需 ONNX Runtime。

**翻译上下文（v1）**：只给**已提交的 ASR 原文**，不给历史译文，也不给当前句的上一个译文版本。
两道预算 `mt.context_sentences`（默认 2 句）与 `mt.context_max_chars`（默认 2000 字符），
任一为 0 关闭，负值启动即报错。最近一句自己就超字符上限时历史为空——不截断、也不跳过它。
原文一定稿就进历史（与翻译成败无关），快照在入队时冻结，晚处理的句子看不到排在它后面的原文。
请求形态是 `system` + 单条 `user`，用 `【前文】`/`【本次原文】` 分区，不构造 assistant 历史译文轮次。
原文和上下文均在入队时冻结；每次原文修订产生版本号，旧译文在流中及流结束后都检查版本。

**草稿译文显示（2026-11-04 修复）**：首次翻译仍流式显示。当前句已有译文时，后续草稿
重译在请求内缓冲，完成且版本仍有效后一次替换，避免完整译文反复回退为开头几个字。
完整的新译文可以比旧译文短；失败或被更新版本取代的缓冲不覆盖显示，也不改变旧译文的原文归属。

**采集跟随**：采集线程每 1 s 比对 Windows 默认端点，变了就重开流；用户显式选的设备优先于自动跟随。
切换丢 0.3–1 s 音频，时间轴按采样累计，不插静音，也不主动 flush 当前句。

**渲染端无状态**：字幕端不存会话，只按 id upsert；外观状态由自己落盘到
`%APPDATA%\simulcast\render.json`，总管的托盘菜单读同一个文件来显示勾选。

## 局限

- 双路（内录 + 麦克风）共用一个 Orchestrator 和一个翻译队列：历史会互相串，两路会互相排队。
- ASR 不给词级时间戳，句子时间是按字符比例估的；srt 能用，逐字高亮不够。
- 跨窗对齐依赖文字密度估计；歧义、模型漏字、极端变速与预算耗尽仍可能导致降级、重复或错句界。
- 自然连续长句缺少人工标注实录验收；已有 25.02 s 重复样本不是自然长句。
- 背景音幻觉尚未解决：仅增加观测能力与失败定稿防护，尚无经独立验证的自动过滤。
- 慢翻译服务下 MT 队列仍可能增长；现有单工队列未做全面负载治理。
- 只实现 `openai-chat` 一种方言；Qwen-MT（`translation_options`）、DashScope multimodal 都要新适配器。
- 只有 Windows 音频采集；没有 TTS、虚拟麦克风、说话人分离。
- 字幕窗固定置顶，不支持多屏。
- 日语动漫效果未系统验证（英语路径验证充分一些）。
- 上下文里的历史只到"前 x 句原文"：术语表、场景预设、滚动摘要都还没做。

## 开发方式

### 环境

```bash
uv venv .venv
uv pip install --python .venv/Scripts/python.exe -r requirements.txt
```

观测模式另需在同一个 Python 环境安装可选的 `onnxruntime`，并自行提供本地
Silero 16 kHz ONNX 模型。设置 `asr.speech_evidence_model`（相对配置文件目录解析）
及 `speech_evidence_mode="observe"`；不自动下载模型。缺模型/运行库会在启动时报告配置错误。
替换 ASR 模型后，应重新验证 `asr.repair_max_s`；类型默认 10 s，本机配置通过单次 30 s 容量探测后设为 30 s。

### 模型服务

应用**不负责**启动服务，需手动开两个 `llama-server`（ASR 18091、MT 18092）。
本机脚本 `scripts/serve-local.ps1` 只用于自己电脑，被 `.gitignore` 挡住，不进仓库。

### 运行

```bat
run.bat          :: 总管（托盘 + 两个引擎）
tools\devices.bat :: 列出采集设备
```

### 测试

```powershell
& '.venv/Scripts/python.exe' tools/check.py
# 也可只跑指定脚本
& '.venv/Scripts/python.exe' tools/check.py test_utterances test_pipeline_shutdown
```

仓库里只留不依赖音频设备/模型服务/显示器的测试；需要真实服务的脚本留在本机
（`test/test_capture.py`、`test/test_qt.py`、`test/test_render_live.py`、`test/test_render_shot.py`），
音频样本放 `test/fixtures/`（本地生成，同样不入库）。

2026-11-04 完整检查：**37 PASS / 0 FAIL / 0 SKIP**，耗时 18.1 s；包含重译显示、
较短译文替换、过时流丢弃，以及失败后不把旧译文确认为新原文译文的回归。
本次未重跑真实模型与音频设备验收。
